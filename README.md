# AI/Human Text Analysis Studio

This project explores supervised text mining and classification to analyze differences between texts written by humans and texts generated by AI systems. It combines classical NLP, feature engineering, model comparison, and an interactive Dash application for evaluating and classifying text.

> Important notice: this is an experimental academic project. Model predictions are not definitive proof of authorship. Performance depends on the dataset, preprocessing choices, and the specific run configuration.

## Overview

The repository implements a full text analysis workflow:

1. loading the original, cleaned, or debug dataset;
2. cleaning and normalizing text;
3. exploratory data analysis;
4. training several classification models;
5. comparing them using evaluation metrics;
6. performing sensitivity analysis for texts of different lengths;
7. exporting metrics, tables, plots, and models;
8. classifying text entered by the user;
9. visualizing results through a Dash application;
10. classifying text obtained from the web when the feature and network connection are available.

The notebook presents the complete methodological study. The Dash application provides a more accessible interface for consulting results, exploring models, and analyzing texts.

## Objectives

- Investigate whether lexical and statistical features can distinguish human-written text from AI-generated text.
- Compare traditional text representations, embeddings, and machine learning approaches.
- Evaluate model behavior using metrics such as accuracy, precision, recall, F1-score, and ROC-AUC when computed by the notebook.
- Explore differences in length, vocabulary, lexical diversity, POS tagging, and named entities.
- Provide an interface to experiment with classifications and consult the study results.

## Preprocessing

The `clean_text_english` function applies suitable operations for the English corpus:

- lowercase conversion;
- removal of numbers;
- punctuation removal;
- whitespace normalization;
- removal of stop words from NLTK and scikit-learn;
- removal of very short tokens;
- stemming with `SnowballStemmer("english")`.

The notebook currently recalculates the `clean_text` column during the main execution even when that column already exists. To avoid unnecessary work in future runs, it can be preserved after the first preprocessing step.

## Models evaluated

The study compares the following approaches:

| Model | Representation / technique |
| --- | --- |
| Bag of Words + Logistic Regression | Term frequency and logistic regression |
| TF-IDF + LinearSVC | TF-IDF weighting and linear SVM classifier |
| TF-IDF + Multinomial Naive Bayes | TF-IDF and multinomial Naive Bayes |
| Word2Vec + Logistic Regression | Aggregated Word2Vec embeddings and logistic regression |
| TF-IDF + XGBoost | Textual features and XGBoost classifier |
| TF-IDF + neural network | Textual features and a Keras/TensorFlow neural network |

The names of the persisted artifacts and some configuration details are centralized in [`config/settings.py`](config/settings.py).

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/IlieIftime/ProjetoTextmining.git
cd ProjetoTextmining
```

If the data or models are managed by Git LFS:

```bash
git lfs install
git lfs pull
```

### 2. Create and activate a virtual environment

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

Windows CMD:

```bat
python -m venv .venv
.venv\Scripts\activate
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install the application dependencies

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The `requirements.txt` covers the main dependencies for the Dash app, including pandas, Plotly, scikit-learn, TensorFlow, XGBoost, newspaper3k, requests, and Beautiful Soup.

### Additional notebook dependencies

The notebook also imports libraries that are not all declared in `requirements.txt`, including NLTK components, Gensim, spaCy, Matplotlib, Seaborn, WordCloud, tqdm, textstat, SHAP, and others.

To run all notebook cells, install the required packages in the same environment, for example:

```bash
python -m pip install matplotlib seaborn tqdm wordcloud nltk gensim spacy textstat shap duckduckgo_search
```

Then download the necessary NLTK resources:

```bash
python -c "import nltk; nltk.download('stopwords')"
```

Some cells may also require a spaCy model or additional resources. Install them only if used by the current version of the notebook:

```bash
python -m spacy download en_core_web_sm
```

> These additional dependencies are documented here to reflect the current notebook. The file `requirements.txt` is not altered by this README.

## Configuration and debug mode

In the notebook, the main execution flags are:

```python
FAST_MODE = False
USE_DEBUG_DATASET = False
N_PER_CLASS = 225000
```

- `USE_DEBUG_DATASET = True`: uses `data_debug/AI_Human_debug_subset.csv` when the file exists.
- `FAST_MODE = True`: creates a subsample by class from the loaded dataset.
- `N_PER_CLASS`: defines the maximum number of examples per class used in the subset.

For local development, a smaller configuration may be more suitable:

```python
FAST_MODE = True
USE_DEBUG_DATASET = True
N_PER_CLASS = 1000
```

After changing these flags, rerun the loading and modeling cells to ensure all results belong to the same subset.

## Limitations and reproducibility

- A detector trained on this dataset may learn corpus-specific features instead of generalizing to other topics, authors, time periods, or generative models.
- Classification is probabilistic and can produce false positives and false negatives.
- Cleaning with stemming removes linguistic information and may affect interpretability.
- Results depend on the train/test split, sampling, hyperparameters, and library versions.
- Models should not be used in isolation for academic, professional, legal, or disciplinary decisions.
- Web analysis depends on network access, site availability, robots.txt restrictions, HTML structure, and the quality of extracted text.
- TensorFlow, XGBoost, and NLP libraries may require compatible Python versions and native dependencies.
- To reproduce results, keep the same data, flags, `random_state`, library versions, and exported artifacts.

Before interpreting results, confirm that the files used by the app correspond to the same execution as the notebook, especially `final_model_comparison.csv`, the model reports, and the generated assets.
